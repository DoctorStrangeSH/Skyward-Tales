# AI HANDOFF — Skyward Tales

Последнее обновление: 2026-11-01.

Этот документ — обязательная точка входа для следующего ИИ-разработчика. Прочитай его и `docs/ROADMAP.md` до изменения кода.

## 1. Видение проекта

Skyward Tales — 2D top-down pixel-art fantasy RPG с исследованием открытого мира, магией, прокачкой, сюжетом, квестами, NPC, подземельями и боссами.

Основной язык игры на текущем этапе — русский. Пользователь — владелец проекта и тестировщик. ИИ выступает техническим лидом: самостоятельно принимает обоснованные инженерные решения, реализует функции, поддерживает документацию и предоставляет пользователю сборки для тестирования.

## 2. Технологии и принципы

- Движок: Godot 4.x.
- Язык: GDScript.
- Жанр/камера: 2D top-down action RPG.
- Внутреннее разрешение: 640×360; окно: 1280×720; nearest texture filtering.
- Репозиторий: https://github.com/DoctorStrangeSH/Skyward-Tales
- Основная ветка: `main`.
- Рабочая ветка первого инкремента: `feat/godot-rpg-foundation`.

Почему Godot: проект ориентирован на 2D, пиксельную графику, частые итерации и модульные игровые системы. Не мигрировать на Unity/Unreal без конкретной технической причины.

Архитектурные принципы:
1. Разделять игровые системы по ответственности.
2. Квесты, заклинания, предметы, врагов и NPC переводить на ресурсы или JSON-данные, а не размножать хардкод.
3. Не помещать всю игру в один огромный скрипт.
4. Сохранять исходники арта и единые правила импорта.
5. Поддерживать русский язык в интерфейсе и контенте.
6. После каждого изменения обновлять ROADMAP и этот HANDOFF.
7. Не утверждать, что тесты пройдены, если Godot действительно не запускался.

- `docs/ROADMAP.md` — этапы и статусы.

## 4. Первый игровой фрагмент

Тестовая сцена задумана как короткий вертикальный срез:

1. Игрок появляется на лесной тропе.
2. Подходит к старейшине Элиану и нажимает E.
3. Принимает квест «Три лунных листа».
4. Собирает три листа, нажимая E рядом с каждым.
5. Возвращается к старейшине и получает 50 опыта и 25 золота.
6. Сражается со слизнями, используя ЛКМ для магического снаряда.
7. Получает опыт и повышает уровень.

Управление:
- WASD / стрелки — движение.
- E — взаимодействие и сбор.
- ЛКМ — чародейский снаряд (цена и урон загружаются из `data/spells.json`).
- Esc — пауза/возобновление.

Во время диалога движение и каст блокируются. Нажми E, чтобы закрыть диалог.

## 5. Важное ограничение текущего состояния

Изменения внесены через GitHub API. В этой среде не был запущен редактор Godot и не выполнялся импорт проекта. Поэтому код следует считать **первой реализацией, ожидающей runtime-проверки**, а не подтверждённой стабильной сборкой.

Первое действие следующего ИИ:
1. Открыть проект актуальной стабильной версией Godot 4.
2. Выполнить импорт и запуск.
3. Исправить все ошибки парсинга/ресурсов.
4. Проверить управление, камеру, паузу, диалоги, квест, коллизии снаряда и слизней.
5. Только после этого отмечать runtime-проверку в ROADMAP как выполненную.

## 6. Следующие инженерные задачи

Приоритет A — стабилизация:
- Проверить синтаксис и запуск в Godot.
- Проверить обработку паузы, ввод с мыши и закрытие диалогов.
- Добавить ограничение мира и реальные препятствия/коллизии.
- Добавить перезарядку заклинаний и отображение стоимости маны.
- Добавить экран начала игры и экран паузы с кнопками.
- Добавить автосохранение и ручное сохранение.

Приоритет B — фундамент RPG:
- Перевести тестовый мир на TileMapLayer и отдельные сцены регионов.
- Ввести Resource-классы для заклинаний, предметов, врагов и квестов.
- Добавить инвентарь и экипировку.
- Добавить сохранение/загрузку состояния мира и персонажа.
- Создать полноценную систему диалогов с вариантами ответов.

Приоритет C — контент:
- Утвердить художественный гайд и тайловую сетку.
- Заменить временную геометрию и примитивные спрайты оригинальной пиксельной графикой.
- Добавить анимации персонажа и врагов.
- Расширять мир регионами, квестовыми цепочками, боссами и сюжетными персонажами.

- Работать небольшими вертикальными срезами.
- Предпочитать отдельные feature-ветки и PR в `main`.
- В описании PR перечислять изменения, тесты и ограничения.
- Не удалять исходники или контент без проверки ссылок и использования.
- После каждого завершённого шага обновлять ROADMAP и HANDOFF.
- Пользователь тестирует Windows-сборки; после стабилизации настроить экспорт и GitHub Actions для EXE.
